# Процедурная реализация алгоритмов (Контрольная точка №2)

---

## 1. Стек технологий и среда выполнения

* **Язык программирования:** Python 3.12 (полная совместимость с Python 3.10+)
* **Парадигма:** Процедурное программирование
  * Чистые функции и процедуры с передачей состояния через аргументы.
  * Базовые структуры данных: `dict`, `list`, `tuple`.
  * Полное отсутствие классов ООП, декораторов `@dataclass` и изменяемого глобального состояния.
  * Вспомогательная процедурная функция генерации мок-данных `get_mock_data()` для обеспечения автономного тестирования.
* **Зависимости:** Внешние сторонние библиотеки **не требуются**. Реализация выполнена исключительно на базе стандартной библиотеки Python (модуль `math`). Спецификация зафиксирована в [`requirements.txt`](requirements.txt).

## 3. Описание реализованных алгоритмов

### Алгоритм 1: `verify_cluster_calibration(projectors_calibration, tolerance_threshold=1.5)`
* **Назначение:** Предсеансовая проверка геометрического и оптического сведения многопроекторного кластера купола, расчет среднеквадратичной погрешности (RMS) отклонения контрольных точек калибровочной сетки и вычисление ширины маски краевого слияния (`edge blending mask`).
* **Формула RMS:**
  $$\text{RMS} = \sqrt{\frac{1}{M} \sum_{i=1}^{M} \left( (x_{\text{act}} - x_{\text{tgt}})^2 + (y_{\text{act}} - y_{\text{tgt}})^2 \right)}$$
* **Алгоритмическая сложность:**
  * По времени: $O(N \cdot M)$, где $N$ — число проекторов в кластере, $M$ — количество точек контрольной сетки каждого проектора.
  * По памяти: $O(N)$ для формирования структуры отчёта кластера.
* **Результат:** Диагностический отчет по каждому проектору (RMS погрешность, максимальный дрейф в пикселях, ширина маски сшивки, статус готовности) и общий вердикт о готовности кластера к сеансу.

### Алгоритм 2: `analyze_session_telemetry(telemetry_logs, total_expected_frames)`
* **Назначение:** Постсеансовый статистический анализ аппаратной и сетевой стабильности воспроизведения на основе журнала инцидентов.
* **Формула индекса стабильности кадрового воспроизведения (FSI):**
  $$\text{FSI} = \max\left(0.0, 100.0 - \text{dropped\_rate} - (\text{total\_incidents} \cdot 0.5)\right)$$
* **Алгоритмическая сложность:**
  * По времени: $O(K)$, где $K$ — количество записей в журнале телеметрии (один линейный проход).
  * По памяти: $O(1)$ (агрегация метрик в результирующий словарь фиксированного размера).
* **Результат:** Суммарное число выпавших кадров, процент выпавших кадров, итоговый индекс стабильности (FSI), долевое распределение по типам сбоев (аппаратные, синхронизация, декодирование) и качественный вердикт.

### Алгоритм 3: `validate_media_package(media_package)`
* **Назначение:** Автоматизированный предсеансовый контроль целостности, комплектности и совместимости полнокупольного медиаконтента (Dome Master). Предотвращает аварийную остановку сеанса из-за отсутствия обязательных дорожек, битых файлов или несовместимых форматов контейнера.
* **Проверяемые критерии:**
  1. *Комплектность медиапакета:* обязательное наличие всех 4 базовых компонентов — файла купольного видеомастера (`dome_master_file`), пространственной аудиодорожки (`audio_file`), файла таймлайн-сценария (`scenario_file`) и контрольной суммы (`checksum`).
  2. *Совместимость формата:* валидация расширения видеофайла (`.mp4`, `.mov`), поддерживаемого аппаратными декодерами кластера.
  3. *Контрольная сумма:* проверка целостности архива/файлов при передаче с хранилища контента.
* **Алгоритмическая сложность:**
  * По времени: $O(F)$, где $F$ — количество обязательных атрибутов и метаданных в пакете (проверка фиксированного набора ключей).
  * По памяти: $O(E)$, где $E$ — количество обнаруженных ошибок (динамический список замечаний `errors`).
* **Результат:** Словарь вида `{"is_valid": bool, "errors": list[str]}` с общим статусом валидации и списком текстовых предупреждений (пуст при успешном прохождении).

### Алгоритм 4: `check_projectors_readiness(projectors_status)`
* **Назначение:** Аппаратная экспресс-диагностика физического состояния кластера проекторов перед подачей команды на запуск показа.
* **Проверяемые параметры телеметрии:**
  1. *Питание:* проектор запущен и находится в рабочем состоянии (`powered_on == True`).
  2. *Температурный режим лазера:* температура лазерно-фосфорного оптического блока не превышает критический порог (`laser_temp_celsius < 70°C`), предотвращая тепловую деградацию матриц и аварийное защитное отключение во время сеанса.
  3. *Линк синхронизации:* наличие устойчивого сетевого соединения между контроллером проектора и медиасервером (`media_server_link == True`).
* **Алгоритмическая сложность:**
  * По времени: $O(N)$, где $N$ — число проекторов в кластере (один линейный цикл по устройствам).
  * По памяти: $O(N)$ в худшем случае для формирования списка идентификаторов проблемных устройств `not_ready_ids`.
* **Результат:** Словарь вида `{"cluster_ready": bool, "not_ready_ids": list[int]}` с интегральным флагом готовности кластера и перечнем ID проекторов, требующих вмешательства инженера.
