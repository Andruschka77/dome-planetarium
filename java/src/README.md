# Объектно-ориентированная реализация ядра системы (Контрольная точка №3)

---

## 1. Стек технологий и среда выполнения

* **Язык программирования:** Java 21 (LTS)
* **Инструмент автоматизации сборки:** Apache Maven 3.9+
* **Парадигма:** Объектно-ориентированное программирование (ООП) с соблюдением принципов SOLID и шаблона проектирования «Стратегия» (Strategy).
* **Библиотеки и зависимости:**
  * **Project Lombok (1.18.32)** — библиотека генерации бойлерплейт-кода (`@Getter`, `@Setter`, `@AllArgsConstructor`).
  * Стандартная библиотека Java: `java.util.List`, `java.util.ArrayList`, `java.util.Map`, `java.util.HashMap`, `java.util.Arrays`.
  * Спецификация сборки зафиксирована в [`pom.xml`](pom.xml).

## 2. Архитектура решения и структура пакетов

Кодовая база состоит из **15 классов и интерфейсов**, логически декомпозированных по пакетам:

```text
java/src/
├── model/                          # Сущности предметной области и персонал
│   ├── Hall.java                   # Купольный зал
│   ├── Projector.java              # Лазерный проектор купольного кластера
│   ├── MediaProgram.java           # Полнокупольная медиапрограмма (Dome Master)
│   ├── ShowSession.java            # Сеанс показа в планетарии
│   ├── SessionProjector.java       # Связующая сущность сеанса и проектора (M:N)
│   ├── TelemetryIncident.java      # Запись журнала инцидентов телеметрии
│   ├── CalibrationProfile.java     # Профиль оптико-геометрической калибровки
│   ├── CalibrationGridPoint.java   # Контрольная точка сетки сведения (Warping)
│   ├── Employee.java               # Абстрактный базовый класс сотрудника («abstract»)
│   ├── Operator.java               # Оператор пульта управления сеансом
│   ├── Engineer.java               # Инженер оптико-аппаратного комплекса
│   └── ContentManager.java         # Менеджер полнокупольного медиаконтента
├── service/                        # Сервисный слой и алгоритмические стратегии
│   ├── CalibrationRule.java        # Интерфейс стратегии расчёта зоны сшивки («interface»)
│   ├── StandardBlendRuleImpl.java  # Стандартная линейная стратегия сшивки (плановая юстировка)
│   └── StrictBlendRuleImpl.java    # Прецизионная ужесточённая стратегия сшивки
├── pom.xml                         # Конфигурация Maven и зависимости Lombok
├── Main.java                       # Точка входа: сборка стенда и прогон всех сценариев
└── README.md                       # Руководство по ООП-модулю (КТ3)
```

## 3. Реализация принципов ООП

1. **Инкапсуляция:**
   * Все поля классов объявлены с модификатором доступа `private`.
   * Доступ к полям строго регламентирован через аннотации `@Getter`, `@Setter` библиотеки Lombok или методы с валидацией инвариантов.
2. **Наследование:**
   * Абстрактный класс `Employee` является общим предком для конкретных ролей: `Operator`, `Engineer`, `ContentManager`.
   * Общие поля (`idEmployee`, `fullName`, `phone`) и поведение инкапсулированы в суперклассе.
3. **Полиморфизм:**
   * Метод `performDuty()` объявлен абстрактным в `Employee` и переопределён в каждом подклассе с учетом должностного регламента. Вызов метода выполняется полиморфно в цикле по списку `List<Employee>`.
   * Стратегии расчета краевого слияния (`StandardBlendRuleImpl` и `StrictBlendRuleImpl`) взаимозаменяемы через общий интерфейс `CalibrationRule`.
4. **Абстракция:**
   * Выделены ключевые абстракции предметной области купольного кинотеатра без привязки к конкретным аппаратным протоколам.
5. **Паттерн «Стратегия» (Strategy):**
   * Алгоритм верификации калибровки `CalibrationProfile.verifyClusterCalibration(...)` принимает интерфейс `CalibrationRule`, что позволяет динамически изменять алгоритм расчета ширины маски сшивки без модификации основного кода (принцип Open-Closed).

## 4. Команды сборки и запуска

### Сборка проекта через Maven:
```bash
cd java/src
mvn clean compile
```

### Запуск программы:
```bash
# Вариант 1: Через Maven Exec Plugin
mvn exec:java -Dexec.mainClass="Main"

# Вариант 2: Прямой запуск скомпилированных классов
java -cp target/classes Main
```

## 5. Реализованные алгоритмы

1. **Алгоритм 1: `CalibrationProfile.verifyClusterCalibration(profiles, threshold, rule)`**
   * Расчет RMS погрешности калибровочных сеток и максимального отклонения точек по каждому проектору.
   * Делегирование вычисления ширины зоны сшивки переданному объекту `rule` (полиморфизм).
   * Формирование типизированного отчета `ClusterReport` с вердиктом о готовности кластера.
2. **Алгоритм 2: `ShowSession.analyzeSessionTelemetry(incidents)`**
   * Анализ журнала инцидентов телеметрии сеанса, расчет выпавших кадров и индекса стабильности воспроизведения (FSI).
   * Категоризация сбоев по типам (аппаратный перегрев, джиттер синхронизации, ошибки декодера) с возвратом объекта `TelemetryStats`.
3. **Операция 3: `MediaProgram.validateMediaPackage()`**
   * Проверка целостности компонентов пакета (наличие файлов купольного мастера, звука 7.1, сценария и MD5-хеша).
4. **Операция 4: `Projector.checkProjectorsReadiness(projectors)`**
   * Статический метод аудита состояния кластера (питание, температурный режим лазеров, линк с медиасервером).
