## Описание проекта
Проект посвящён исследованию архитектуры и разработке программных средств управления купольными проекционными комплексами цифрового планетария (Fulldome).
Разрабатываемое программное обеспечение решает задачи:
* автоматизированной предсеансовой проверки и валидации параметров сферического медиаконтента (Dome Master / Fisheye, разрешение до 8K, кадровая частота, многоканальный звук);
* координации оптико-геометрической калибровки многопроекторного кластера (алгоритмы нелинейной геометрической деформации — *warping* и бесшовного сведения зон перекрытия — *edge blending*);
* диспетчеризации сценария показа и синхронизации воспроизведения аудиовизуальных дорожек;
* централизованного сбора телеметрии оборудования (FPS, температура лазерных источников, пропуски кадров) и протоколирования хода сеансов.

## Процедурная реализация алгоритмов (Контрольная точка №2)

### 1. Стек технологий и среда выполнения
* **Язык программирования:** Python 3.12 (поддерживается Python 3.10+)
* **Парадигма:** Процедурное программирование (2 алгоритма аналитического этапа, вспомогательная функция генерации тестовых данных `get_mock_data()` для обеспечения чистоты кода, точка входа `main()`; базовые структуры данных `dict`, `list`, `tuple`; полное отсутствие ООП-классов, dataclass и изменяемого глобального состояния).
* **Зависимости:** Внешние сторонние библиотеки **не требуются**. Программа разработана исключительно с применением стандартной библиотеки Python (модуль `math`). Спецификация зафиксирована в [`python/requirements.txt`](python/requirements.txt).

### 3. Реализованные алгоритмы аналитического этапа
1. **Алгоритм 1: `verify_cluster_calibration(projectors_calibration, tolerance_threshold=1.5)`**
   * *Назначение:* Проверка оптического сведения кластера проекторов купола перед сеансом и расчёт ширины зоны краевого слияния (`edge blending mask`).
   * *Сложность:* Время — $O(N \cdot M)$ (вложенный цикл по точкам $M$ внутри цикла по проекторам $N$), память — $O(N)$ для формирования структуры отчёта кластера.
   * *Результат:* Диагностический отчёт по каждому проектору (RMS погрешность, максимальный дрейф в пикселях, ширина маски сшивки, статус готовности) и общий вердикт о готовности кластера к показу.

2. **Алгоритм 2: `analyze_session_telemetry(telemetry_logs, total_expected_frames)`**
   * *Назначение:* Статистический анализ стабильности сеанса и структуры зафиксированных инцидентов телеметрии.
   * *Сложность:* Время — $O(K)$ (один линейный проход по журналу инцидентов), память — $O(1)$ (агрегация метрик в результирующий словарь фиксированного размера).
   * *Результат:* Агрегированный отчёт: процент выпавших кадров (`dropped frame rate`), индекс стабильности воспроизведения (`Frame Stability Index`), долевое распределение сбоев по типам и качественный вердикт.
